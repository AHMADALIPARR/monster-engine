machine checkers (`contracts/`), and the dependency-coverage

## Checker results

`contracts/check_contracts.py` (python3 standard library only; exact
integer / `Fraction` arithmetic for the algebraic checks) implements
every finite-check, identity-check and data-check item.
`contracts/run_checks.sh` runs it, saves one line per contract id to
`contracts/check-output.txt`, and exits nonzero if any actual outcome
differs from the expectation encoded in the checker.

Run result: exit code 0 — expected and actual agree on all 28 items.

What the executed checks actually computed:

- S3 finite instance (MON): the Cayley table is constructed in code
  from the permutations of 3 elements, generated by the transposition
  (1,0,2) and the 3-cycle (1,2,0), composed as tuples. Closure 36/36
  products; identity 6/6; inverses 6/6; associativity 216/216 triples.
- Homomorphisms: the sign map S3 → {+1, −1} satisfies
  sign(a·b) = sign(a)·sign(b) for 36/36 pairs (VERIFIED). The constant
  map sending every element to (1,0,2) is detected as a
  non-homomorphism at a = b = (0,1,2), where f(a)·f(b) = (0,1,2) ≠
  (1,0,2) = f(a·b) (COUNTEREXAMPLE, the expected outcome).
- Characters (S3 instance): trivial, sign and standard
  (χ(p) = fix(p) − 1) characters are constant on the computed
  conjugacy classes, pairwise orthonormal, and 1² + 1² + 2² = 6 = |S3|.
  Conjugacy classes: sizes [1, 2, 3], a partition of the 6 elements.
- Moonshine data: the coefficients recorded in `families.json` equal
  the established published values {744, 196884, 21493760, 864299970};
  McKay's identity 196883 + 1 = 196884 holds as exact integers; the
  decompositions 21493760 = 1 + 196883 + 21296876 and
  864299970 = 2·1 + 2·196883 + 21296876 + 842609326 hold as exact
  integers. During development the checker caught a wrong first
  version of the second decomposition (it summed to 864103086);
  the recorded identity is the corrected one above, and the run
  script's nonzero exit on that mismatch is how it was caught.
- Lie algebra (so(3) instance): stored bracket table matches the
  Levi-Civita structure constants on 9/9 basis pairs; antisymmetry
  holds on 9/9 basis pairs and the Jacobi identity on 27/27 basis
  triples, both with maximum residual exactly 0 over the rationals.
  Group-action composition: the C4 action (quarter turns) on the 4
  square vertices satisfies (g+h)·v = g·(h·v) on 64/64 triples.
- Geometry (concrete instances, BOUNDED): dyadic quadtree of the unit
  square to depth 2 — parent measure equals the sum of its 4 children
  at 5/5 internal nodes in exact Fractions, 16 leaves of 1/16 summing
  to 1; integer shear T(x, y) = (x + 2y, y) and its inverse compose to
  the identity on 5 test vectors with residual exactly 0; shapes
  (2,3,4), (4,3,2), (6,4), (24,), (2,12) all have element count 24;
  upsample/downsample reconstruction of f(x) = 2x + 1 on 9 dyadic
  samples has maximum absolute residual 0.0 (< 1e-9); the matrix
  [[1,2,3],[2,4,6],[1,1,1]] has rank 2 under exact rational
  elimination, unchanged by the stated row and column permutations.

## Optimisation instance

Model: minimum-cost set of verification tasks covering all 20
checkable contract items (one covering constraint per item; binary
task variables). Because every checkable item's `depends_on` targets
are themselves checkable (asserted in the brute-force script), any
feasible cover is dependency-closed.

- Tasks: 12 — mon_core (4), mon_repr (4), mon_full (7), moon_data (3),
  moon_j (2), lie_bracket (3), lie_full (5), lie_action (2),
  geo_grid (3), geo_full (5), geo_measure (3), cross_finite (2).
  Costs are in abstract task units; each task's covered subset is
  named in `ampl/coverage.lp`, `ampl/coverage.mod` and
  `ampl/coverage_brute.py`. The brute-force script parses
  `coverage.lp` and asserts its objective coefficients and covering
  constraints equal its own task table, so the solver model and the
  enumeration cannot drift apart silently.
- Constraints: 20 covering constraints, 12 binary variables.
- Solver: HiGHS 1.15.1 (`~/workspace/.tools/highs/bin/highs`) on
  `ampl/coverage.lp`, run by `ampl/run_coverage.sh`; full output in
  `ampl/coverage-run.txt`. Status: Optimal, primal bound 20, dual
  bound 20, gap 0%.
- Brute force: `ampl/coverage_brute.py` enumerates all 4096 task
  subsets. True optimum: cost 20, attained by exactly 2 optimal sets:
  {mon_full, moon_data, lie_full, geo_full} and
  {mon_full, moon_data, lie_bracket, lie_action, geo_full}.
- Agreement: solver objective 20 equals brute-force optimum 20.
  `run_coverage.sh` exits nonzero if they ever disagree. Re-running
  it regenerates `coverage-run.txt` with identical results; only
  HiGHS's own timing fields (solve seconds, P-D integral) vary
  between runs.
- `ampl/coverage.mod` is the same model in AMPL syntax. It is a
  separate artifact and was not executed by AMPL: AMPL is not
  installed, and the file's header says so. Execution was by HiGHS on
  the LP file only.

An optimisation result prioritises verification work; it certifies
nothing mathematical.

## What is NOT checked, and why

- The Monster group itself: no enumeration and no direct check is
  performed. Its order is about 8.08×10^53, no validated Monster
  character table or generator set is an input to this package, and
  the finite checks above concern S3, a named finite test instance.
  S3 results prove nothing about the Monster. The Monster appears
  only as the abstract-only item MON-monster-abstract, reported
  UNSUPPORTED.
- Full moonshine theory: only the concrete published numbers are
  data-checked (J coefficients, McKay's identity, and the two
  coefficient decompositions, all as exact integer arithmetic on
  established published values). Checking the arithmetic does not
  prove the representation-theoretic correspondence. Modular
  transformation identities (analytic, no modular-forms library is an
  input here), the McKay–Thompson genus-zero correspondence, and the
  graded-module / partition-function constraints (statements over
  infinitely many graded pieces, requiring vertex-operator-algebra
  machinery) are abstract-only and UNSUPPORTED here.
- Differential-geometric Lie items: tangent-space consistency,
  equivariance of smooth actions, and coordinate-chart compatibility
  require smooth-manifold machinery that is not an input to this
  package. Only the exact finite instances are checked: the so(3)
  bracket on a 3-dimensional basis and the finite C4 action law.
  Neither establishes any positive-dimensional Lie-group statement.
- Geometry beyond the stated instances: the GEO checks are evidence
  on the concrete grids, transforms, shapes, matrix and signal named
  in `families.json`, reported BOUNDED. They are not proofs for
  arbitrary subdivisions, transforms or tensors. Holographic duality
  (GEO-holographic-scope) is abstract-only: no check in this package
  produces evidence for it.
